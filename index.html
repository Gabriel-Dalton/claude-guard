claude-guard

Lets Claude Code work. Stops it from wrecking your machine.

A PreToolUse hook that scores every shell command on a 0 to 100 risk scale, silently allows the safe ones, asks on ambiguous ones, and blocks the obviously dangerous ones.

the problem

Three paths. One of them is right.

option a / too noisy

Default Claude Code

Approves nothing without asking. You click through dozens of prompts a day for commands that are obviously fine. A normal pwsh -DryRun gets flagged as a "nested PowerShell process which cannot be validated." Your flow dies a death by a thousand confirmations.

option b / too loose

--dangerously-skip-permissions

Approves everything. Claude can install packages, modify files outside the project, talk to the network, and run things as you, all without asking. The noise is gone. So is the safety net.

option c / claude-guard

The middle path

Silent on the boring stuff. Asks on ambiguous things, with a full risk breakdown. Hard-blocks supply-chain attacks, credential reads, force-pushes to main, and 200,000+ named-malicious packages. The judgement call you'd make if you reviewed every command yourself. Encoded.

how it works

Score every command. Map to a decision.

Before Claude runs a shell command, claude-guard sees it via the PreToolUse hook. Four signal types fire in parallel: pattern matches (regex on known dangerous shapes), path scope (where on the filesystem the command reaches), network targets (domain reputation, package registries), and contextual reducers (dry-run flags, read-only verbs). Anomaly detection adds a small overlay based on what's normal for this project. The total clamps to 0 to 100 and maps to one of three decisions.

Real examples, from the live test suite

0/100 git status allow / allowlist hit
0/100 pip install requests==2.31.0 allow / pinned, not malicious
10/100 git push --force origin feature/foo allow / force push on a feature branch
25/100 New-NetFirewallRule -DisplayName foo -Direction Inbound ask / firewall rule modification

60/100 git push --force origin main deny / force push to protected branch
80/100 npm install snes-game-names deny / real OSV MAL-* typosquat
100/100 rm -rf / deny / denylist match

what's inside

Six things that make it actually work.

threat feed

223,000+ malicious packages, auto-refreshed

Live OSV.dev MAL-* advisories for npm and PyPI, pulled with a single script. Catches typosquats and supply-chain attacks the moment Claude tries to install one. Schedule it via cron or Task Scheduler; the hook reads the latest set on every invocation.

llm second opinion

Haiku 4.5 weighs in on the ambiguous middle

Optional, requires ANTHROPIC_API_KEY. Ask-band commands get a 3 second LLM review with the full risk breakdown. High-confidence "allow" verdicts auto-apply. "Deny" verdicts annotate the human prompt with strong warnings, never block on the human's behalf.

anomaly detection

Per-project behavioural baselines

Tracks which interpreters, domains, and directories are normal for each project. A first-time fetch to a never-seen domain adds points. Catches prompt-injection cases that static pattern rules can't see. Warmup is 50 commands; baseline updates only on allowed decisions.

self-tuning

Learns the commands you keep approving

Run tune.py review after a week of real use. It reads your audit log, clusters the commands you keep getting prompted on, and promotes them to a silent-allow with one keypress. Writes to rules_user.py so upstream updates never clobber your tuning.

audit log

Every decision recorded as JSONL

Per-command timing, signal breakdown, decision rationale, LLM verdict if it ran. Local file, append-only, no rotation. Pipe it through jq, feed it into your own dashboards, or just grep it. The audit log is the API; tune.py and anomaly both read from it.

fail-closed

If the hook breaks, you get prompted

A syntax error in rules.py, a malformed audit file, a corrupted threat feed: none of these silently bypass Claude Code's permission system. The default failure mode is to ask the human, with an explanation of what went wrong. Configurable via FAIL_MODE in rules.py.

install

Three steps. Or really, one.

01

Run the one line

The installer asks if you want global (every Claude Code project on this machine, recommended for daily use) or per-project (just one folder). It copies the files, merges the hook into the right settings.json, and optionally fetches the malicious-package feed. Re-running it is idempotent.

macOS / Linux

$ git clone https://github.com/Gabriel-Dalton/claude-guard ~/.claude/guard \
    && python ~/.claude/guard/install.py

Windows (PowerShell)

> git clone https://github.com/Gabriel-Dalton/claude-guard `
    "$env:USERPROFILE\.claude\guard"; `
  python "$env:USERPROFILE\.claude\guard\install.py"
02

Optional: the LLM key

For the Haiku 4.5 second opinion on ambiguous commands. claude-guard works without this; you just don't get the LLM review. If you set it, the hook calls api.anthropic.com only for commands in the ask band (score 25 to 59), with a 3 second hard timeout.

# bash / zsh
$ export ANTHROPIC_API_KEY="sk-ant-..."

# PowerShell (persistent across sessions)
> setx ANTHROPIC_API_KEY "sk-ant-..."
03

Open a Claude Code session

That's it. The hook fires on every Bash command Claude tries to run. The boring stuff goes through silently. Ambiguous stuff still asks. Dangerous stuff gets blocked. After a week, run tune.py review to cut down the asks even further.

questions you'll have

Things worth knowing.

Does it slow down Claude Code?

Per-command evaluation is sub-millisecond after pre-compile. Cold start (Python launch plus loading the threat feed) is around 350ms on a typical machine. The 95th percentile end-to-end stays under the 1 second budget we wrote into the spec, with plenty of margin.

Does it phone home?

No. The hook itself makes zero network calls. The threat feed updater talks to OSV.dev on your schedule, when you run it. The LLM fallback talks to api.anthropic.com only if you opt in by setting ANTHROPIC_API_KEY. There is no telemetry, no usage reporting, no analytics, no nothing.

What if claude-guard itself breaks?

Default fail-mode is "closed." If rules.py has a syntax error, or any unexpected exception fires during evaluation, the hook emits an explanatory "ask" decision so you get prompted. It never silently bypasses Claude Code's permission system. The behaviour is configurable in rules.py if you'd rather fail open.

Can I tune it for my workflows?

Yes. After a week of real use, run python tune.py review. It clusters the ask-band commands you keep getting prompted on, suggests an allowlist regex for each cluster, and writes them to rules_user.py on your approval. The base rules.py is never modified; pulling updates from the repo stays clean.

Do I need the LLM API key for it to work?

No. Everything works without it. The key only enables the optional Haiku 4.5 second-opinion on the ambiguous middle band. You get pattern, path, network, anomaly, and context scoring regardless. The LLM is a nice extra, not the core.

How do I uninstall it?

Delete the install directory (rm -rf ~/.claude/guard for global, or <project>/.claude/guard for per-project), then remove the PreToolUse Bash hook entry from the matching settings.json. The installer prints the exact paths when it finishes, so you don't have to hunt for them.

Is it Windows-friendly?

Yes. Designed and tested on Windows 11 with PowerShell as a first-class shell. Path normalisation treats \ and / as equivalent. PowerShell-style commands get their own detection layer. The installer's settings.json merge handles both POSIX and Windows-style hook command paths.
